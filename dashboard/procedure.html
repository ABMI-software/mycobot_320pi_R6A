1

Créer l'écran

Deux commandes et une entrée dans une liste. Le menu, l'adresse et la carte de l'accueil se créent tout seuls.

  1. Générer le composant

    Dans un terminal, à la racine du projet mycobot-dashboard :

    terminal
    npx ng generate component views/pince

    Angular crée le dossier src/app/views/pince/ avec quatre fichiers : le code (pince.ts), la page (pince.html), le style (pince.scss) et le test (pince.spec.ts).

  2. Déclarer l'écran dans le registre

    Ouvrir src/app/views/views.ts et ajouter un bloc à la liste VIEWS (lignes en vert) :

    src/app/views/views.ts
    export const VIEWS: readonly DashboardView[] = [  {    path: 'joints',    // ... écran existant ...  },  {    path: 'pince',                       // adresse : #/pince    title: 'Pince',                      // nom dans le menu    icon: 'target',                      // icône (liste dans shared/icon/icon.ts)    description: 'Ouvrir et fermer la pince du robot.',    loadComponent: () => import('./pince/pince').then((m) => m.Pince),  },];

    C'est tout pour la navigation : l'écran apparaît dans le menu de gauche, sur l'accueil, et à l'adresse #/pince.

  3. Écrire le contenu de la page

    Toujours la même structure : un en-tête page-head, puis des cartes card. Les styles sont déjà prêts dans src/styles.scss, il n'y a rien à dessiner.

    src/app/views/pince/pince.html
    <header class="page-head">  <p class="eyebrow">Outil</p>  <h1>Pince</h1>  <p class="lead">Ouvrir ou fermer la pince du robot.</p></header><section class="card">  <header class="card-head">    <h2 class="card-title">Commande</h2>  </header>  <div class="card-body">    <button class="btn btn-primary" [disabled]="!robot.connected()" (click)="open()">Ouvrir la pince</button>    <button class="btn btn-secondary" [disabled]="!robot.connected()" (click)="close()">Fermer la pince</button>    @if (error(); as message) {      <div class="alert" role="alert">{{ message }}</div>    }  </div></section>

2

Le connecter au robot

Un écran ne parle jamais directement à ROS. Il appelle RobotService, qui s'occupe du reste.

Ton écranpince.ts→ RobotServicerobot.service.ts→ rosbridgeWebSocket :9090→ topic /to_robotJSON→ Raspberry Pibridge_pi_simple.py→ Bras

Les réponses de la Pi (« OK: … » ou « ERROR: … ») reviennent par le topic /from_robot et s'affichent automatiquement en notification. L'écran n'a rien à faire pour ça.

Cas 1 : la commande existe déjà

RobotService sait déjà faire : sendAngles(angles, vitesse), sendCoords(coords, vitesse), goHome(), goZero(), powerOn(), readAngles() et readCoords() (lecture de la pose réelle). Il suffit de l'injecter et de l'appeler (voir le code de pince.ts plus bas, le principe est le même).

Cas 2 : ajouter une nouvelle commande

Exemple avec la pince : la Pi connaît déjà les actions gripper_open et gripper_close.

D'après la documentation du dépôt, aucune pince n'est montée sur le robot actuel. L'exemple sert à montrer la méthode : le tester avec le faux robot ou avec ros2 topic echo, pas sur le bras.

  1. Déclarer la commande dans RobotService

    Dans src/app/core/robot/robot.service.ts, ajouter le format JSON de la commande et une méthode pour l'envoyer :

    src/app/core/robot/robot.service.ts
    export type RobotCommand =  | { action: 'send_angles'; angles: number[]; speed: number }  | { action: 'go_home' }  | { action: 'gripper_open' }  | { action: 'gripper_close' };// ... plus bas, dans la classe RobotService, à côté de goHome() :  /** Ouvre la pince. */  openGripper(): void {    this.send({ action: 'gripper_open' });  }  /** Ferme la pince. */  closeGripper(): void {    this.send({ action: 'gripper_close' });  }

    Le nom de l'action et ses paramètres doivent correspondre exactement à ce qu'attend la Pi (fichier bridge_pi_simple.py, méthode execute_json). Actions disponibles : send_angles, send_coords, go_home, go_zero, gripper_open, gripper_close, get_angles, power_on, power_off.

    Ne pas utiliser emergency_stop : côté Pi, cette action relâche tous les moteurs et le bras tombe.

    Si la commande a des paramètres (angles, vitesse…), les vérifier avant l'envoi comme le fait sendAngles : une valeur hors limites lève une erreur et rien n'est envoyé.

  2. Appeler la commande depuis l'écran
    src/app/views/pince/pince.ts
    import { ChangeDetectionStrategy, Component, inject, signal } from '@angular/core';import { RobotService } from '../../core/robot/robot.service';@Component({  selector: 'app-pince',  templateUrl: './pince.html',  styleUrl: './pince.scss',  changeDetection: ChangeDetectionStrategy.OnPush,})export class Pince {  // Accès au robot (connexion, commandes, réponses)  protected readonly robot = inject(RobotService);  protected readonly error = signal<string | null>(null);  protected open(): void {    this.run(() => this.robot.openGripper());  }  protected close(): void {    this.run(() => this.robot.closeGripper());  }  /** Envoie la commande ; en cas de problème, affiche le message au lieu de planter. */  private run(command: () => void): void {    this.error.set(null);    try {      command();    } catch (e) {      this.error.set(e instanceof Error ? e.message : String(e));    }  }}

    Les trois réflexes à garder pour chaque bouton qui commande le robot :

    RéflexeComment
    Bouton grisé hors connexion[disabled]="!robot.connected()"
    Erreur affichée, pas de plantageappel dans try / catch → signal error
    Aucun JSON écrit dans l'écrantoujours passer par une méthode de RobotService
  3. Apprendre la commande au faux robot

    Pour tester sans robot, le faux rosbridge doit savoir répondre. Dans tools/mock-rosbridge.mjs, fonction fakePiReply :

    tools/mock-rosbridge.mjs
        case 'go_home':      return 'OK: retour home';    case 'gripper_open':      return 'OK: pince ouverte';    case 'gripper_close':      return 'OK: pince fermée';    default:      return `ERROR: action inconnue ${command.action}`;

    Sans cet ajout, le faux robot répond « ERROR: action inconnue gripper_open ». C'est normal, et ça prouve que la commande est bien partie.

Cas 3 : afficher des données du robot

Les dernières réponses de la Pi sont déjà disponibles : robot.lastFeedback() (le dernier message) et robot.feedbackLog() (les 50 derniers). Dans la page : {{ robot.lastFeedback() }}.

Pour un autre topic ROS (positions, caméra…), on s'abonne avec RosClient et on transforme le flux en signal :

exemple
private readonly ros = inject(RosClient);// Se met à jour tout seul à chaque message reçu sur le topicprotected readonly etat = toSignal(  this.ros.subscribe<MonMessage>('/nom_du_topic', 'paquet/msg/Type'),);

Le topic doit exister côté ROS. Pour le vérifier sur la tour : ros2 topic list, puis ros2 topic info /nom_du_topic pour connaître son type.

3

Tester

Trois niveaux, du plus rapide au plus réel.

  1. Test automatique

    On remplace le vrai robot par FakeRosClient, qui enregistre tout ce qui est envoyé. On clique sur le bouton et on vérifie le JSON :

    src/app/views/pince/pince.spec.ts
    import { TestBed } from '@angular/core/testing';import { RosClient } from '../../core/ros/ros-client';import { FakeRosClient } from '../../core/ros/testing/fake-ros-client';import { Pince } from './pince';describe('Pince', () => {  it('envoie gripper_open quand on clique sur « Ouvrir la pince »', async () => {    const ros = new FakeRosClient();    TestBed.configureTestingModule({      imports: [Pince],      providers: [{ provide: RosClient, useValue: ros }],    });    const fixture = TestBed.createComponent(Pince);    await fixture.whenStable();    const buttons: HTMLButtonElement[] = Array.from(fixture.nativeElement.querySelectorAll('button'));    buttons.find((b) => b.textContent?.includes('Ouvrir la pince'))!.click();    const last = ros.published.at(-1)!;    expect(last.topic).toBe('/to_robot');    expect(JSON.parse((last.message as { data: string }).data)).toEqual({ action: 'gripper_open' });  });});
    terminal
    npm test
  2. Dans le navigateur, avec le faux robot
    deux terminaux
    npm run mock:ros     # terminal 1 : faux rosbridgenpm start            # terminal 2 : http://localhost:4200

    Ouvrir l'écran depuis le menu, cliquer : une notification verte « OK: pince ouverte » doit apparaître en haut à droite.

  3. Sur la tour, avec le vrai robot

    D'abord sans lancer bridge_tour, pour voir ce que l'écran envoie sans faire bouger le bras :

    tour (ROS2)
    ros2 launch rosbridge_server rosbridge_websocket_launch.xmlros2 topic echo /to_robot std_msgs/msg/String     # autre terminal

    En cliquant, on doit lire data: '{"action":"gripper_open"}'. Ensuite seulement, lancer bridge_tour et essayer sur le robot.

    Avec le vrai bras : arrêt d'urgence physique à portée de main, vitesse basse (20) et petits mouvements pour commencer.
